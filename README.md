# MOOT

Персональный ассистент в боковой панели Chrome. Текст, голос и действия на странице работают в одном разговоре.

## Запуск

1. Установи Node.js 20.19+ и выполни `npm install`, затем `npm run build`.
2. Открой `chrome://extensions`, включи режим разработчика.
3. Нажми «Загрузить распакованное расширение» и выбери **папку dist**. Также поддерживается загрузка корня проекта `Agent-Moot`; иконки и исходники находятся на месте.
4. Открой MOOT через значок расширения. В настройках укажи свой OpenAI API-ключ и доступные твоему аккаунту модели.
5. После обновления сборки нажми «Обновить» у расширения и заново открой панель MOOT. Если на уже открытой странице нет обработчика сообщений, расширение подключит скрипты автоматически. При запрещённом доступе к сайту появится пояснение.

Ключ хранится локально в профиле браузера. Запросы модели, записи произнесённых фраз и текст для озвучивания отправляются в OpenAI. История чатов хранится в IndexedDB. Старые ключи хранилища сохранены для совместимости с историей MUT.

## Разговор голосом

Нажми «Начать разговор» **один раз** и разреши доступ к микрофону. MOOT отправляет реплику автоматически после паузы около 850 мс. Тишина и короткие щелчки не отправляются. Длинная реплика ограничена 20 секундами.

Во время выполнения задачи микрофон продолжает слушать. Начало следующей фразы прерывает ответ и останавливает предыдущую задачу. После распознавания новая команда выполняется в том же чате. «Стоп» отменяет задачу; кнопка «Завершить» или Escape также выключает микрофон. При закрытии панели микрофон освобождается.

Это автоматический разговор через распознавание → модель → озвучивание, поэтому пауза ответа зависит от сети и API. Пока распознаётся отправленная фраза, интерфейс показывает «Распознаю фразу»; следующую произноси после «Слушаю». Эхоподавление включено; на громких динамиках лучше использовать наушники. Качество распознавания, перебивания и порог чувствительности нужно проверить на реальном микрофоне.

## Интерфейс

- Векторный знак MOOT и иконки расширения 16/32/48/128 px.
- Адаптивный тёмный интерфейс, подсказки, история и настройки.
- Enter отправляет сообщение, Shift+Enter добавляет строку.
- Голосовые реплики сохраняются в той же истории, что и текст.
- Кнопка звука включает озвучивание текстовых ответов. В голосовом разговоре ответы озвучиваются автоматически.

## Надёжность

### Постоянный мониторинг чата

Пример поручения: «Следи за этим чатом и отвечай на новые вопросы коротко и дружелюбно. Продолжай, пока я не скажу стоп».

MOOT сохраняет независимые наблюдения через инструмент `monitor`: можно одновременно следить за чатами WhatsApp, Telegram и Discord. Для каждого чата нужна отдельная вкладка. В панели показан список со статусами и индивидуальными кнопками остановки; «Стоп все» выключает все наблюдения. Старое сохранённое наблюдение переносится вместе с очередью сообщений.

Во время мониторинга можно давать новые команды текстом или голосом, например: «Открой WhatsApp, прочитай новые сообщения и отправь сводку в Избранное Telegram». Агент получает список наблюдаемых вкладок и использует отдельные рабочие вкладки, если переход заменил бы наблюдаемый чат. Пока он выполняет обычное поручение, входящие сообщения накапливаются в очередях; после завершения автоответы возобновляются. Мониторинг не ограничивает инструменты основной задачи. Сообщения собеседников не становятся командами пользователя MOOT.

Обычное завершение задачи, открытие истории или настроек, окончание голосового разговора и закрытие панели не выключают мониторинг. Общая команда «Стоп» выключает все наблюдения. Для остановки одного чата можно назвать его или нажать его кнопку «Остановить».

Новые сообщения отслеживаются через изменения страницы; резервная проверка запускается раз в минуту через `chrome.alarms`. В состоянии ожидания модель не вызывается. Запросы на новые сообщения используют настроенную быструю модель и оплачиваются по API. Задание, очередь сообщений, последние идентификаторы и журнал действий сохраняются в `chrome.storage.local`. При неопределённом результате отправки действие не повторяется после восстановления фонового процесса.

Браузер и вкладка нужного чата должны оставаться открытыми, компьютер — работать. Панель MOOT можно закрыть. При переключении на другой чат в наблюдаемой вкладке работа ждёт возвращения в выбранный чат. При недоступной вкладке, сети или API мониторинг сохраняется и повторяет проверку позже; причина видна в панели. Сон компьютера, заморозка/выгрузка вкладок браузером и закрытие браузера прерывают своевременное получение событий. После запуска браузера восстанавливается резервное расписание; может потребоваться снова открыть нужный чат.

Для надёжного наблюдения нужны стабильные идентификаторы сообщений и корректные селекторы из текущего интерфейса. История, уже видимая при запуске, не вызывает ответов. Известные исходящие сообщения и текст недавних автоответов пропускаются. При полной замене видимой истории мониторинг устанавливает новую исходную точку, не отвечая на старые сообщения. Это наблюдение через веб-интерфейс, а не серверная подписка: нельзя гарантировать получение сообщений, которые сайт не загрузил в DOM. Дополнительные действия в выбранном чате включаются только по поручению пользователя; на одно входящее сообщение выполняется один ответ или одно действие.

Проверка: `npm run test:monitor`. Тесты используют отдельный профиль браузера, подставные страницы трёх мессенджеров и ответы API. Проверяются одновременные наблюдения, обычная отправка при включённом мониторинге, очереди во время другой задачи, возобновление, индивидуальная остановка, работа при закрытой панели и восстановление журнала без повторной отправки. Реальные аккаунты не используются.

Сохранение состояния и резервные пробуждения учитывают [жизненный цикл фонового процесса Chrome](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle).

### WhatsApp Web, Telegram Web и Discord Web

Инструмент `messenger` показывает видимые чаты, поля, заголовки, списки сообщений и прокручиваемые панели. MOOT открывает найденный чат, сверяет заголовок и вводит черновик. Перед отправкой проверяет, что текст сохранился и открыт нужный чат. Результат подтверждается по появлению нового сообщения в переписке; это не подтверждение доставки или прочтения.

Поиск, меню и остальные доступные элементы управляются обычными инструментами страницы. Прокрутка поддерживает отдельный контейнер через `target`. Неоднозначные и отсутствующие цели больше не заменяются случайной кнопкой.

Редактируемые поля используют браузерный механизм ввода с проверкой результата, включая переносы строк и эмодзи. Изменение текста через `textContent` для ввода удалено. Один запрос на отправку не повторяется при потере ответа; проверка сохраняется в `chrome.storage.session` на время сессии браузера. Неопределённый результат нужно проверить в истории, прежде чем отправлять повторно.

Вход в аккаунты выполняет пользователь. Проверки `npm run test:messengers` используют локальные подставные страницы на перехваченных адресах трёх сервисов и не отправляют сообщения реальным людям. Это проверка механизмов, а не подтверждение работы всех вариантов текущего интерфейса сервисов. Реальные аккаунты пока не проверены. Изменения сайтов, ограничения автоматизации и нестандартные редакторы могут потребовать дополнительной настройки.

Механизм редактирования основан на [браузерном insertText/insertLineBreak](https://developer.mozilla.org/en-US/docs/Web/API/Document/execCommand); его работа проверяется в Chromium, поскольку API устарел и поведение браузеров различается.

Остановка отменяет запросы модели и озвучивания, отбрасывает поздние ответы и проверяется перед следующим действием. Уже выполненный клик не отменяется. Ошибки ключа, доступа и лимитов не запускают пять одинаковых повторов. Инструменты вызываются последовательно, а контекст страницы не дублируется в запросе.

MOOT выполняет понятные поручения через доступные браузерные инструменты. Возможности сайтов, разрешения Chrome и правила провайдера модели по-прежнему действуют. Расширение не управляет системными страницами Chrome или рабочим столом.

## Проверки

```sh
npm test
npm run build
npx playwright install chromium
npm run test:extension
```

Модульные тесты проверяют определение конца фразы, отмену позднего действия, обработку ошибок API, форму запроса и тайм-аут тела ответа. Браузерная проверка загружает настоящую сборку расширения в отдельный временный профиль Chromium, использует тестовые ответы API и искусственный микрофон. Проверяет интерфейс на ширинах 320/400/600 px, настройки, историю, голосовой режим и остановку. Снимки сохраняются в `artifacts/`.

Проверка с настоящим API, реальным микрофоном и целевыми сайтами требует локального запуска пользователем. Тестовый сценарий не использует пользовательский профиль браузера или настоящий API-ключ.

Вызовы инструментов согласованы с [официальной документацией OpenAI](https://developers.openai.com/api/docs/guides/function-calling).
